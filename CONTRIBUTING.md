# Contributing

Contributions are welcome. Keep terminal UI changes focused and preserve keyboard-driven behavior unless the pull request intentionally changes it.

## Workflow

1. Branch from `main`.
2. Follow the setup and run instructions in `README.md`.
3. Keep each pull request limited to one logical feature, fix, or documentation change.
4. Run the relevant formatter, linter, build, and tests available in the repository.
5. Describe the user-visible effect and how it was verified.

For TUI changes, note terminal size assumptions, keyboard bindings, and rendering changes when relevant. Include terminal output or screenshots if they help review. Do not commit credentials, caches, generated build output, or editor-specific files.
